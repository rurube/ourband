# 이전 엑셀 투표 집계

이전 브라우저 기반 투표자 해시는 Supabase Auth 계정과 자동으로 연결할 수 없습니다. 엑셀의 투표 시트는 `(곡 ID, 투표자 해시)`별 최신 행으로 중복을 정리한 뒤, 곡별 좋아요·별로예요 수로 가져옵니다. 투표자 해시를 새 계정으로 만들거나 현재 회원에게 배정하지 않습니다.

`private.legacy_song_votes`는 곡 ID, 좋아요·별로예요 수, 원본 파일 SHA-256과 가져온 시각만 저장합니다. 원본 곡 ID로 연결하고, 같은 곡을 다시 가져올 때는 `ON CONFLICT(song_id) DO UPDATE`로 스냅샷을 교체합니다. 기존 집계에 같은 파일을 반복해서 더하지 않습니다. 이관된 집계의 개별 표는 현재 로그인 계정으로 취소할 수 없습니다. 같은 사람이 새 앱에서 투표하더라도 이전 해시와 연결하지 않으므로 새 계정 투표로 별도 합산됩니다.

`get_song_stats`와 `list_song_catalog`는 **이전 집계 + 현재 Auth 회원 투표**를 반환합니다. 카드, 좋아요순·순추천순 정렬, 확정곡, 인기곡에 같은 기준을 사용합니다. `get_my_votes`와 `toggle_vote`는 현재 계정의 투표만 다루며, 본인 표를 취소해도 이전 집계는 유지합니다. 이전 표가 있는 밴드는 화면에 이 구분을 안내합니다.

집계 원본 테이블은 RLS를 활성화하고 일반 회원·비회원의 직접 접근을 차단합니다. 공개 함수도 실제 밴드 소속을 검사하고 곡 ID로 범위를 제한합니다. 회원이 보게 되는 것은 집계이며 원본 투표자 해시는 DB에 보관하지 않습니다.

## 변경 파일과 검증

- `supabase/migrations/20261105080000_legacy_vote_totals.sql`: 이전 집계 테이블과 기존 조회 RPC 보강
- `supabase/test-support/legacy-votes.sql`: 중복 재이관, 현재 표 선택·취소, 밴드 격리·개인정보와 인기 정렬 검증 15개
- `src/songs/api.ts`, `src/pages/SongsPage.tsx`, `src/styles.css`: 최근 추가곡 10개와 키보드로도 스크롤할 수 있는 목록
- 로컬 DB 검증 320개 및 프런트 타입 검사·빌드 통과
- 실제 데이터 반영은 대상 밴드·회원·원본 곡 ID와 제목/가수, 원본 합계를 검증하고 한 트랜잭션으로 적용했습니다. 현재 앱의 투표 행을 변경하지 않았습니다.

최근 추가곡은 등록 시각 내림차순·ID 순으로 10곡을 조회합니다. 목록 내부를 스크롤하며, 데스크톱 최대 높이 520px, 모바일 360px입니다.

## 배포 이력

이번 집계 마이그레이션만 운영 DB에 선택 적용하고 마이그레이션 이력에 기록했습니다. 보류된 `20261105070100_rehearsal_write_permissions.sql`은 적용하지 않았습니다. 후속 전체 DB 배포 시 이 미적용 항목을 확인하고 사용자의 기존 선택을 유지해야 합니다.

투표 데이터를 담은 파일이나 SQL, 실제 밴드·회원 식별자는 공개 저장소에 추가하지 않습니다. 재이관은 원본을 검증한 뒤 대상 곡별 집계를 교체하며 현재 앱 투표를 수정하지 않습니다. Realtime 또는 다른 회원 투표의 자동 갱신은 별도 기능입니다.
