# 내 가능 세션과 메인 포지션

**우리 밴드 → 개인 설정 · 내 포지션**에서 가능한 세션을 여러 개 선택하고, 그중 하나를 메인 포지션으로 지정합니다. 보컬·기타·베이스·드럼·건반을 지원합니다. 밴드별로 저장하므로 다른 밴드에서는 다른 포지션을 사용할 수 있습니다.

가능 세션을 처음 선택하면 그 세션을 메인으로 제안하며 드롭다운에서 변경할 수 있습니다. 메인으로 지정한 세션을 체크 해제하면 남은 선택 중 하나가 메인이 됩니다. 모든 체크를 해제하고 저장하면 미설정 상태로 돌아갑니다. 기존 회원에게 포지션을 임의로 배정하지 않습니다.

멤버 목록에는 선택한 가능 세션과 메인 표시를 보여줍니다. 합주 세션 배정의 멤버 선택지에도 해당 세션의 `메인` 또는 `가능` 표시를 붙입니다. 포지션은 배정을 돕는 자기소개 정보이며 다른 세션으로의 배정을 막지 않습니다. 저장된 과거 합주 배정을 변경하지 않습니다.

## 데이터와 권한

`20261105090000_member_session_preferences.sql`은 `band_memberships`에 다음 필드를 추가합니다.

- `available_sessions text[] NOT NULL DEFAULT '{}'`
- `main_session text NULL`

DB CHECK는 유효한 세션 종류·중복 없는 1차원 배열·메인 포함 여부를 보장합니다. 가능한 세션이 하나 이상이면 메인은 반드시 그중 하나이며, 가능 세션이 없으면 메인도 NULL이어야 합니다.

`set_my_band_sessions(p_band_id,p_available,p_main)`는 Auth UUID와 실제 밴드 소속으로 본인의 행만 갱신합니다. 대상 사용자 인자를 받지 않아 리더도 다른 사람의 설정을 대리 수정할 수 없습니다. 일반 회원의 테이블 직접 UPDATE 권한은 부여하지 않습니다. 기존 멤버 목록 RLS를 유지하므로 다른 밴드의 설정이 새로 공개되지 않습니다.

편집 입력은 재조회·저장 실패 때 유지하고, 저장 요청 중 중복 클릭과 편집을 잠급니다. 저장 후 본인 소속 정보·밴드 멤버 목록·합주 멤버 선택 목록 캐시를 갱신합니다. 밴드 전환 시 폼은 해당 밴드의 저장 값으로 새로 구성됩니다.

- 프런트 타입 검사·빌드 통과

이번 기능의 마이그레이션만 원격에 선택 적용하고 이력에 기록합니다. 이전에 보류한 `20261105070100_rehearsal_write_permissions.sql`은 포함하지 않습니다. 추가 환경변수나 서버 비밀값은 필요하지 않습니다.

## 5종 세션 통일

`20261105100000_five_session_types.sql`부터 세션은 보컬·기타·베이스·드럼·건반으로 통일합니다. 기존 `guitar1`·`guitar2`는 `guitar`로 합치며 개인 설정의 중복 선택도 정리하고 메인 포지션을 유지합니다. 한 곡의 두 기타 슬롯에 같은 회원이 있으면 한 기타 배정으로 합칩니다. 게스트는 같은 이름만으로 같은 사람이라고 판단하지 않아 각각 유지합니다. 종류를 바꾸면서 기존 닉네임 기록을 현재 닉네임으로 덮어쓰지 않습니다.

분류가 없는 기존 `other` 합주 배정이 있다면 자동으로 다른 악기에 배정하지 않고 이전 작업을 중단해 별도 확인하도록 했습니다. 실제 원격 반영 전 조회에서 해당 배정은 없었습니다. 개인 설정의 제거된 종류는 선택 목록에서 제외하며 메인이 제거되면 남은 첫 포지션 또는 미설정으로 정리합니다.

현재 DB 검증은 348개이며 기타 병합·배정 ID·닉네임 기록 보존 검증 6개를 포함합니다. 이번 종류 통일만 선택 적용했으며 보류 중인 합주 직접 쓰기 권한 변경은 적용하지 않았습니다.
