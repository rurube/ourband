# Phase 5 — 투표·익명 댓글·인기곡·합주 확정

## 사용 방법

희망곡 카드에서 좋아요 또는 별로예요를 선택합니다. 같은 버튼을 다시 누르면 취소하고 반대 버튼을 누르면 변경합니다. 선택은 계정 UUID 기준이며 밴드 닉네임을 바꿔도 유지됩니다. 투표자 목록은 제공하지 않습니다.

제목·댓글 버튼·최근 등록곡·인기곡을 누르면 곡 상세 대화상자를 엽니다. 상세 화면에서 곡 정보 수정, 투표, 합주 확정, 익명 댓글 조회와 작성을 할 수 있습니다. 댓글은 최대 300 Unicode 코드 포인트이며 작성자 이름·ID 대신 익명과 한국 시간의 작성 시각만 표시합니다. 최신 20개부터 읽고 더 보기로 이전 댓글을 불러옵니다. 댓글 초안은 재조회나 요청 실패 때 유지됩니다. 등록에 실패해 결과를 확인하지 못했다면 새로고침으로 반영 여부를 확인한 뒤 재시도합니다. 자동 재전송하지 않습니다.

메인화면의 밴드별 카드와 희망곡 화면의 상단 인기곡은 여보컬·남보컬 각각 미확정곡 중 좋아요가 가장 많은 곡입니다. 동률은 최신 등록, 이후 곡 ID 순입니다. 0표면 인기곡 없음으로 표시합니다. 최근 5곡은 확정 여부를 포함해 표시하며 상세 화면을 엽니다.

모든 밴드 구성원이 카드의 합주 확정을 체크하거나 해제할 수 있습니다. 확정곡은 일반 목록에서 빠지고 기본 접힘 상태인 확정곡 목록에 모입니다. 해제하면 일반 목록으로 돌아옵니다. 메인화면의 전체 밴드 확정곡도 갱신합니다. 실제 합주 날짜·세션은 별도 데이터이며 변경하지 않습니다.

## 서버와 개인정보

기존 `toggle_vote`, `get_my_votes`, `get_song_stats`, `list_song_catalog`를 재사용합니다. 투표는 DB의 `(song_id,user_id)` PK 및 계정·곡 단위 트랜잭션 잠금으로 직렬화합니다. 브라우저는 대상 user_id를 보낼 수 없습니다. 같은 계정의 다른 기기도 동일한 투표를 공유합니다.

`20261105060000_song_engagement.sql`은 최신 댓글 조회용 `list_song_comments`와 인덱스를 추가하고 `add_comment`의 공백·300자 검사를 보강합니다. 모든 함수는 현재 요청의 실제 밴드 소속을 재확인하며 `x-band-id`를 클라이언트 권한으로 신뢰하지 않습니다. 비회원 함수 실행은 차단합니다. `private.votes`와 `private.comments`의 원본 데이터는 REST에 공개하지 않습니다.

```text
list_song_comments(p_song_id, p_before_time=null, p_before_id=null, p_limit=20)
→ [{id, song_id, content, created_at}]
```

커서는 `(created_at,id)` 내림차순 키셋입니다. 두 커서 인자는 함께 전달해야 하며 최대 50개로 제한합니다. 댓글이 추가돼도 다음 페이지가 밀리지 않고 동일 작성 시각은 UUID로 순서를 결정합니다. 작성 응답도 위 익명 필드만 반환합니다. 기존 오프셋 댓글 RPC는 호환성을 위해 유지합니다.

확정·해제는 band_id·곡 ID·기존 updated_at이 일치하는 행만 갱신합니다. 다른 멤버가 먼저 수정하면 최신 내용을 읽고 다시 시도하도록 안내합니다. ID·등록 시각·댓글·투표·합주 관계는 유지합니다.

## 화면 상태와 요청 수

- 페이지의 곡 ID들을 모아 통계와 본인 투표를 각각 한 번씩 조회합니다. 카드마다 별도 초기 요청을 보내지 않습니다.
- 본인 투표를 포함한 각 곡의 상태를 계정·밴드·곡 ID로 캐시하며 투표는 낙관적으로 반영합니다. 실패하면 해당 곡만 되돌립니다. 서로 다른 곡의 동시 변경이 다른 곡의 롤백에 영향을 주지 않습니다.
- 진행 중인 투표와 서버 조회 결과를 별도 상태로 유지합니다. 재조회가 진행 중인 표시를 덮어쓰지 않고, DB가 반환한 최종 투표를 반영한 뒤 집계를 재확인합니다.
- 같은 곡의 중복 클릭은 요청 중 잠그며 투표·댓글 쓰기에 자동 재시도하지 않습니다.
- 투표 후 현재 밴드의 집계·목록·인기곡, 댓글 후 해당 댓글과 집계를 갱신합니다. 확정 변경은 해당 밴드 목록과 메인 확정곡도 갱신합니다.
- 대화상자는 네이티브 dialog를 사용하며 Escape·닫기·키보드 포커스 이동을 지원합니다. 댓글과 곡 텍스트는 React 텍스트로 출력하고 HTML로 해석하지 않습니다.
- Realtime 연결과 다른 기기의 즉시 알림은 Phase 7 범위입니다. 현재는 화면 재진입·포커스 복귀·새로고침 및 본인 변경 후 재조회로 갱신합니다.

## 검증과 배포

```sh
npm run test:db
npm run test:songs
npm run check:edge
npm run test:edge
npm run build
```

- DB 검증 264개: 기존 238개 + 현재 Phase 5 검증 26개
- 곡 입력 및 투표 상태·댓글 검사 9개
- 실제 원격 Auth/REST Phase 5 검증 34개: 동시 투표 직렬화, 투표 선택·취소·변경, 밴드 격리, 익명 응답, 댓글 커서·입력 제한, 인기곡 동률과 0표, 확정·해제와 수정 충돌
- QA 계정·밴드·곡·댓글·투표만 생성 후 정리하며 기존 사용자의 데이터는 사용하지 않음
- 브라우저 자동화 연결 제한으로 실제 클릭·모바일 시각 검증은 미완료. 네이티브 dialog의 포커스·스크롤 및 모바일 배치는 후속 수동 확인 대상
- 기존 Edge secrets·프런트 환경변수 그대로 사용하며 추가 사용자 설정 없음

원격 테스트의 `TEST_SUPABASE_URL`, `TEST_SUPABASE_PUBLISHABLE_KEY`, `TEST_SUPABASE_SERVICE_KEY`는 QA 실행 프로세스 환경에만 전달합니다. 관리자 키는 파일이나 프런트 환경변수에 저장하지 않습니다. Docker를 사용할 때의 pgTAP 래퍼는 `supabase/tests/database/song-engagement.test.sql`입니다.
